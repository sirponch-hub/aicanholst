# Вёрстка доски: кадры и типографика

Правила выведены из практики: доски, свёрстанные иначе, на воркшопе не читаются.

## Кадр — это экран, а не полотно

Главная ошибка при генерации досок: верстать широкие фреймы, куда влезает много
всего. Человек смотрит доску на мониторе 16:9. Если кадр шире, он выбирает между
«вижу целиком, но не читаю» и «читаю, но не вижу задание». Оба варианта плохие.

**Правило: один кадр — один экран — одна задача.** Все фреймы делай строго 16:9
(рабочий размер `4800 × 2700`) и клади внутрь всё, что нужно для одного шага:
заголовок, формулировку задания и рабочую область.

Отсюда следствия:

- **Не ставь несколько команд рядом на одном широком листе.** Если упражнение
  делают 3 команды — это 3 отдельных кадра 16:9, и задание продублировано в каждом.
  Так участник открывает свой кадр во весь экран и видит всё.
- **Не ставь несколько кейсов/вариантов на один кадр.** Пять кейсов — пять кадров.
- Имя фрейма (`labelText`) — это навигация в панели Холста. Пиши туда осмысленное
  название кадра, включая номер команды: «Кого затронут изменения — Команда 2».
  **Одинаковых имён быть не должно**, иначе в панели кадры неразличимы.

Если кадр остаётся полупустым — это нормально: лучше воздух, чем мелкий шрифт.
Если не влезает — дели на два кадра, а не уменьшай кегль.

### Раскладка: день → модуль → строка

Не выстраивай все кадры в одну ленту. Читаемая доска — это колонка из строк:

- **Строка** — логическая группа: теория, потом упражнение команд, потом ревью,
  потом дебриф. 1–5 кадров в строке.
- **Модуль** — несколько строк с подписью-заголовком сверху. Между модулями разрыв
  больше, чем между строками.
- **День/раздел** — разрыв ещё больше плюс крупная подпись и линия во всю ширину доски.

Ориентиры: между кадрами в строке 420, между строками 460, между модулями 900,
между днями 2400.

## Типографика: смотри на кадр как на слайд презентации

Кегль задавай **в процентах от высоты кадра**, а не «на глаз». Для кадра высотой 2700:

| Роль текста | Доля высоты | Кегль при H=2700 |
|---|---|---|
| Заголовок кадра | 6–8% | 165–220 |
| Задание / подзаголовок | 2,6–3% | 70–85 |
| Текст в блоках, подписи колонок | 3% | ~85 |
| Мелкие подписи в плотных таблицах | 2,2% — это пол | 60 |

**Ничего мельче 2% высоты кадра на доске быть не должно.** Кегль 24–40, привычный
по вёрстке документов, на кадре 4800×2700 нечитаем — это примерно 1% высоты.

Пересчёт кегля:

- `shape.font_size` — абсолютные пиксели. Ставь сразу целевое значение.
- `text(scale=...)` — множитель; фактический кегль ≈ `14 × scale`. Значит заголовок
  это `scale ≈ 12`, тело `scale ≈ 6`.

### Высота фигуры считается от текста, а не наоборот

Самая частая ошибка после кеглей: полоса задана фиксированной высотой, а текст в неё
«впихивается» и обрезается снизу. Правильный порядок обратный — сначала считаешь,
сколько текст займёт, потом задаёшь высоту.

Для этого есть `box_h(text, w, fs)`. Порядок действий в `shape()`:

1. Ужать кегль до пола `FS_FLOOR = 60` (`autofit=True`).
2. Если и так не влезает — **вырастить саму фигуру** (`grow=True`, включено по умолчанию).

Обрезанного текста быть не должно ни при каких условиях.

```python
h = box_h(caption, col_w, 90, minimum=190)     # высота полосы — от текста
b.shape(x, y, col_w, h, caption, font_size=90, parent=f)
```

Ориентиры высоты полосы-заголовка при кегле ~90: одна строка — **не меньше 170–190**,
две — 260–280, три — 350–380. Полосы высотой 90–130, привычные по мелкому кеглю,
гарантированно обрежут текст.

Интерлиньяж в расчётах бери **1,45**, не 1,28: реальный рендер Холста выше
типографской нормы, и на 1,28 всё считается впритык. Плюс вертикальные поля внутри
фигуры ~0,6 кегля (`BOX_PAD`).

### Автоподгонка

Оборачивай в `fit_scale` каждый заголовок и каждое задание:

```python
ts = fit_scale(title, W - 2 * PAD, 285, 12.0, floor=6.0)   # заголовок в полосу 285px
b.text(x + PAD, y + 110, title, scale=ts, width=int((W - 2*PAD)/ts),
       halign="center", fixed_width=True, bold=True, parent=f)
```

Заголовок и задание обязаны сами уменьшаться до своей полосы, иначе длинный заголовок
наедет на задание, а задание — на рабочую область. Для текста внутри фигур `shape()`
делает это сам.

### Три ловушки

1. **Стикер нельзя использовать как текстовый баннер.** `scale` тянет и ширину, и
   высоту: `sticker(width=384, height=192, scale=10)` даёт блок 3840×1920 и вылезает
   из кадра. Для широкой плашки с текстом бери `shape` — у неё ширина и высота
   независимы.
2. **`bounds.height` у `simple-text` — не высота текста.** Библиотека пишет туда
   `40 × scale`, а реально текст занимает `число_строк × кегль × 1.45`. Планируй
   вертикаль по фактической высоте, иначе длинный текст наедет на то, что ниже.
3. **Подпись к фигуре центрируй по оси фигуры.** Текст с `halign="left"` и
   фиксированной шириной, положенный рядом с центрированным кругом или схемой, уезжает
   к левому краю блока и визуально отрывается от того, что подписывает. Ставь
   `halign="center"` и ширину, равную ширине блока с фигурой. Арифметическая проверка
   этого не ловит — только глаз.

## Картинки из исходных материалов

Если есть исходник (PDF презентации, старая доска), вытащи картинки и поставь их
вместо перерисовки — это и быстрее, и точнее:

```python
import pymupdf                       # pip install pymupdf
doc = pymupdf.open("source.pdf")
for pno in range(doc.page_count):
    for xref, smask, w, h, *_ in doc[pno].get_images(full=True):
        if w * h < 200000:            # отсечь иконки-повторы
            continue
        pix = pymupdf.Pixmap(doc, xref)
        if smask:                     # прозрачность лежит отдельным объектом
            pix = pymupdf.Pixmap(pix, pymupdf.Pixmap(doc, smask))
        if pix.n - pix.alpha > 3:
            pix = pymupdf.Pixmap(pymupdf.csRGB, pix)
        pix.save("img/p%02d_x%d.png" % (pno + 1, xref))
```

Дальше собери контактный лист (все картинки плиткой в один PNG), **посмотри его
глазами** и отбери нужные. Перед вставкой ужми до ширины ~1800–2000 — иначе `.holst`
распухнет на десятки мегабайт.

Вставляй через `image_fit` — она сохраняет пропорции и центрирует картинку в области.

**Если картинка — готовый слайд со своим заголовком, не добавляй свой сверху.**
Отдай ей весь кадр целиком; при необходимости оставь снизу одну цветную плашку с выводом.

**Прикидывай читаемость картинки заранее.** Корпусный текст на слайде занимает
примерно 1,2% его ширины. Значит на кадре шириной 4400 он даст ~50 px (1,9% высоты
кадра), а если поставить картинку в полкадра — ~30 px (1,1%), вдвое ниже порога.
Практический вывод: картинка-слайд с мелким текстом либо занимает кадр целиком, либо
не ставится вообще. Рабочую область при этом выноси на соседний кадр.
